# Smooth Curve prototype checkpoint and slider experiment

## Checkpoint: first integration (recorded retrospectively)

Enabled Smooth Curve using the existing selection, preview, and Apply workflow.
The independent node fitter feeds a horizontal cubic reconstruction step. Endpoint
nodes and junctions are pinned; elevations and topology are preserved. Added job
lifetime synchronization, rejection feedback, and Debug JSON geometry traces in
Player.log. Release excludes managed trace formatting.

Earlier full Debug and Release builds passed, including Windows Burst compilation;
Debug was deployed. External geometry checks passed again at this checkpoint.
Release execution in-game has not been tested.

Dan tested roads/tracks distorted with Move It. Apply looked acceptable in the
first trial; preview/Apply disagreement was not established. The initial report
included an apparent midpoint jump. A later screenshot sweep instead showed a
large zero-to-positive change with little further visible response. A gray wedge
appeared alongside the preview; its cause remains unknown.

In the captured four-node path, maximum node/handle displacement in metres was:

| Strength | Node | Handle |
| --- | ---: | ---: |
| 0 | 0 | 0 |
| 0.001 | 0 at logged precision | 81.6821 |
| 0.1 | 0.0044 | 81.6807 |
| 1 | 0.3803 | 81.5524 |

These are requested geometry measurements, not rendered road displacement.
The code fully reconstructs handles at every positive strength. This explains a
discontinuity even when the node fitter barely moves anything. Tests of the fitter
alone did not cover this integration behavior.

Move It screenshots also distinguish interior control handles from segment endpoint
controls. Pulling neighboring endpoints apart stretches the visible connection;
moving both together shifts it. Screenshots do not establish changes to stored
node-center coordinates. Node centers and cubic endpoints must remain distinct.

## Experiment 2: continuous handle adjustment

Added a pure `BlendHandle` operation and called it from the game adapter after
target reconstruction. Each original handle first follows its own endpoint's
translation, then blends toward the target by strength. Zero remains untouched;
one reaches the previous full-strength target. The node fitter is unchanged.

The regression uses the actual second handle of captured edge 111496:1 (trace
566). A sweep from 0.000001 through 1 now has proportional displacement: at .001
the isolated handle adjustment is about .08168 m rather than 81.68 m. Endpoint
translation is checked separately. All external geometry tests passed, and Debug
ResolveReferences/Compile passed with existing warnings. This is not a full build,
Burst verification, deployment, or in-game validation of the new change.

Limitations: interpolation retains some original defects at partial strength;
target validation does not prove blended control polygons are loop-free. Invalid
targets still reject the operation. Shared tangents are only the full-strength
target, not guaranteed during blending. Stretched connections and the gray wedge
remain unresolved. This intentionally small experiment isolates slider response
before changing the fitting objective or game connection reconstruction.
