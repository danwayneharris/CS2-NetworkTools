# F13: fail-closed parameter code generation

Current PR #13 generator still silently skipped unsupported enum expressions,
resolved unknown members/modes to zero, ignored unsupported initializers, accepted
empty output, and parsed without game configuration symbols. These audit findings
remain applicable. The bounded correction preserves the existing generator and
adds explicit diagnostics rather than adopting a source-generator framework.

Added source-located NTGEN001 errors for unresolved/unsupported emitted expressions,
missing required arguments, duplicate parameter/generated short keys, ambiguous or
unsupported referenced enums, malformed numeric/boolean/string metadata, unsupported
initializers and unexpected empty results. Output is written only after validation;
negative tests verify the existing output remains untouched. Parsing now honors
Debug/Release/I18N symbols from the pinned Common props plus optional --define.
The supported syntax subset and limitations are in NetworkTools.Codegen/README.md.

Before changes, saved complete Debug and Release generated files under ignored
artifacts. Current source produces 54 parameters, 6 enums and 1 metadata enum in
both configurations. After changes the full generated files compare byte-for-byte
(after Python newline normalization) equal to those originals. Tests also retain
line-order-independent full-output SHA256 checks so filesystem traversal order does
not masquerade as a metadata change.

Standalone generator build: zero warnings/errors. `check-codegen.py`: 5 test methods
pass, covering current output hashes, explicit golden styles/defaults/mode masks,
configuration branches, 14 malformed-expression/argument cases with file/line
checks, and 7 enum/key/empty-output failures. No mod build/deployment/game queries
were performed. Arbitrary C# constant evaluation, namespace/alias semantic binding,
and runtime-only vector/callback validation remain deliberately outside scope.

The existing enum option disabled behavior (Debug permits disabled experimental
options, Release emits disabled:true) was kept unchanged. Parsing I18N uses its
actual symbols but retains existing non-Debug emission policy.
