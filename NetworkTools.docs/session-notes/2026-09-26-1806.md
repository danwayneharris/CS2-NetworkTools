## Experiment 2: continuous handle adjustment

Added a pure `BlendHandle` operation and called it from the game adapter after
target reconstruction. Each original handle first follows its own endpoint's
translation, then blends toward the target by strength. Zero remains untouched;
one reaches the previous full-strength target. The node fitter is unchanged.

The regression uses the actual second handle of captured edge 111496:1 (trace
566). A sweep from 0.000001 through 1 now has proportional displacement: at .001
the isolated handle adjustment is about .08168 m rather than 81.68 m. Endpoint
translation is checked separately. All external geometry tests passed, and Debug
ResolveReferences/Compile passed with existing warnings. This is not a full build,
Burst verification, deployment, or in-game validation of the new change.

Limitations: interpolation retains some original defects at partial strength;
target validation does not prove blended control polygons are loop-free. Invalid
targets still reject the operation. Shared tangents are only the full-strength
target, not guaranteed during blending. Stretched connections and the gray wedge
remain unresolved. This intentionally small experiment isolates slider response
before changing the fitting objective or game connection reconstruction.

## Target-first reconstruction and slope comparison

Added independent `PlanarCubic` evaluation, derivatives, and exact interval slicing.
The external `TargetReplay` experiment reads trace 239, reverses stored edges into
path order, and constructs one boundary cubic using the selected outer endpoints
and their existing tangent directions, with chord/3 handle lengths. This is an
explicit simple target policy, not an optimized general road alignment.

The target is partitioned into two exact cubics at the original node chord-length
ratio. This parameter station is not an arc-length station. The interior node and
both incident endpoints move onto the target; no interior offset is preserved.
The experiment blends all controls toward this fixed target. It remains offline:
the game adapter still uses the deployed node-fairing and handle-blend algorithm.

Results: all external tests passed. At 1001 samples, maximum double-coordinate
reconstruction error was 1.91e-12 m, normalized tangent cross product 1.29e-15,
and maximum error after casting controls to game-sized floats was 0.00010725 m.
The middle node moves 3.858 m. Endpoint separation closes proportionally to
1-strength in the tested sweep. These are planar checks, not vertical continuity,
intersection mesh, terrain, or routing checks. Generated plots 03 and 04 were
visually reviewed; dotted gap markers are never a simulated game connection.

Reproduce from the repository root:

```powershell
dotnet run --project NetworkTools.Geometry.Tests --configuration Release -- NetworkTools.Geometry.Tests/Fixtures/endpoint-offset-239.json NetworkTools.docs/session-notes/plots/target-replay.json
```

Slope provided a useful source-grounded precedent: `SlopeEaseInOutTransform.cs`
builds one reference height curve in PreProcess (line 21), samples endpoint heights
(53-54), and derives handle heights from slopes (63-64). `SlopeUtils` changes only
the four Y values, respecting traversal direction. `TransformPipeline.cs` derives
interior node displacement by averaging adjacent endpoint displacements (79).
Smooth Curve currently bypasses that averaging because it explicitly fits nodes.

## Integrating the target experiment

Added allocation-free `PlanarPathTarget.Fit` and switched `CurveSmoothTransform`
to it. The adapter maps stored edge orientation to path order and back, preserves
every Y value, checks finite float conversion, and publishes only on success.
The module builds the same boundary cubic used in replay, partitions by original
node chord ratios, and blends nodes plus all controls. Existing offsets at outer
selection boundaries remain unchanged; distorted interior offsets are free.

The captured fixture now exercises the actual production math against the
independent target reconstruction across the strength sweep. Tests also cover
reversal, fixed boundary nodes, interior-pin rejection, and NaN strength rejection.
All external tests passed. The generic node-fairing module remains available but
is no longer called by Smooth Curve. Node rotations are not recomputed in this
experiment; existing Apply behavior is unchanged, which remains an integration
limitation to investigate.

Scope is deliberately explicit: positive strength rejects interior junctions and
paths whose node chords turn back along the overall boundary chord. It is not a
general solution for hairpins or route preservation. Coincident interior endpoints
and preserved Y values must be evaluated in-game. The source inspection informed
this experiment but does not establish that every prefab will reconstruct correctly.
